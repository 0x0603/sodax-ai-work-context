## Findings (feedback for the MCP)

1. **README config doesn't work in Claude Code.** Without `"type": "http"` Claude Code silently drops the server
   (only the wallet loaded). Add `"type": "http"` to the snippets or a `claude mcp add --transport http …` line.
2. **Dead default Ethereum RPC** (`eth.merkle.io`, SDK default): track and balance on Ethereum fail; a random hash
   gets "temporary, wait 30 s" instead of "not found". Production must set `SODAX_RPC_URL_<id>` for every EVM source
   (U1); consider the quote probe.
3. **`AMOUNT_TOO_LOW` without the minimum.** The agent probes and overshoots (1.5 vs ≈1.05). Return the minimum (BE
   or an MCP hint).
4. **Polling cost.** 9 track calls back to back in one turn ($0.38). Supports U4 (bounded wait inside track).
5. **Approve not awaited.** Twice the agent sent the swap right after the approve ("nonce keeps the order") although
   the next step says each confirmed before the next; the wallet had no receipt tool. Harmless here; a failed approve
   would revert the swap. Consider wording that says why, or pointing to the batch.
6. **Restart recovery costs a call.** `QUOTE_NOT_FOUND` then retry with `chain` works; the message could say the
   server may have restarted.
7. **`solved` + `delivery: in_transit`** while the funds had already arrived; the agent checked balances itself.
8. **Logs.** A successful submit isn't logged at info (operators can't see which swaps went through); the canary
   oracle 502 is logged at error on every quote (noise).
9. **Builder tools helped, no confusion seen.** In `all` the agent used `docs_query_*` to verify the asset manager
   and the relay tools to confirm delivery; it never reached for `sodax_relay_submit_tx` or `sodax_get_solver_quote`
   (U7 risk not observed).

Validated live: C2 (step `chainId` + "switch" next step: the agent switched from Ethereum), U10 numeric `amount`,
U11 n/a, partner fee paths, non-EVM destination handling, secret handling, restart recovery, idempotent track
(no resubmit across 9 calls; submits aren't logged, see 8).

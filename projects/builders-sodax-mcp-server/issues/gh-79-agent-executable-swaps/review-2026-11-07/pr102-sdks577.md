## #102 (code at `c665c75`)

Checked and right:

- `checkTs`, lint, unit tests (841) pass.
- Kill switch, run locally. Off: `?profile=swap` gets 400 "turned off"; a keyed `all` connection gets builder tools
  only. On: keyless `?profile=swap` gets 403; `/health` shows `swap: 5` and `swapQuotes {open: 0, openUntil: null}`.
- Tool names, headers and query params match README, `server.json` and the landing page. `openQuotes` matches the
  README (not handed over, not expired, until deadline + 30 min).
- Recovering a stranded deposit works as described: `sodax_relay_submit_tx` takes the relay chain id and tx hash;
  the relay chain-id map is keyed by chain key, which the alert carries; the backend canceller works from the hub
  orderbook (`sodax-backend` `intent-canceller.service.ts`), so a relayed intent is refunded the same way track's
  refund relay is.

Should-fix:

   name 295; `parseRpcOverrides` maps `SODAX_RPC_URL_295` to Hedera. Add 295 to both.

   those are capped at 5 posts/h, shared with `other_quote_deposit`; the rest only reach the logs
   (`alert: "unknown_quote"`), with one hourly "N more … only logged" post. A restart that strands several deposits
   hides most of them. Also the first track call without the quote returns `QUOTE_NOT_FOUND` asking for `chain`
   (`source.ts:75-80`); the alert fires only on the retry. Say both. (Fixing `pr95.md` c changes this text.)
3. README.md:394 "Before a deploy … check `/health`": deploys run automatically on merge (README:358-364), so the
   wait has to happen before merging into master (and into development for staging). Say so.
4. PR body "Behavior changes" misses two builder-user changes:
   - `x-api-key` is now forwarded on data API and solver calls (`http.ts:30-33,128`) with no keyless fallback. A key
     the gateway refuses now breaks builder tools that used to work.
   - Server instructions change: keyless `all` connections get a key hint; keyed `all` connections get a line
     steering swaps away from the relay and solver-quote tools (`server.ts:61-62`).
   - Also stale: #100 is already in the stack (development is an ancestor of the tip), #104 still open, test count
     says 749 not 841.

## Pre-release gaps (vs R0bi7's 11-07 list)

- Owners: "someone watching the swap alerts" names nobody. Name owners for the alerts, manual relays, the kill switch
  and the paid RPC accounts.
- RPC 1/137/295: on the checklist, but README and `.env.example` disagree (item 1).
- Gateway: the checklist only tests a fake key against a quote. Also check what a fake or revoked key does to the
  builder data tools (item 4).
- Single replica: listed. Open: the Dockerfile and compose healthcheck may let Coolify run a rolling deploy with old
  and new containers briefly together. Confirm the deploy mode.
- Drain: not on the checklist, and the code has no drain mode. Nothing stops new quotes while track keeps working;
  the kill switch removes track too and needs a restart. Add "check `/health` before merging the release to
  master" (and decide on the hard-drain follow-up offered on 11-04).
- Webhook: swap alerts share `DISCORD_WEBHOOK_URL` with status and drift posts, under the cap. Confirm the channel
  and that whoever watches it knows to check the logs.
- Real canary through arrival: the `canary-e2e` environment doesn't exist (repo has only `copilot`) and
  `e2e-canary.yml` isn't on development yet. Missing from the checklist: create the environment (development only);
  add its secrets (`E2E_WALLET_PRIVATE_KEY`, `E2E_SODAX_API_KEY`, `DISCORD_WEBHOOK_URL`, RPCs); fund the wallet.
  The canary runs its own server in CI, not the deployed one, so it doesn't prove production RPC, webhook or
  gateway setup.

## R0bi7's points

### (a) Contract-test import: confirmed

- `swapTrack.contract.test.ts:16` imports `callTool` from `__fixtures__/swapClient.js`; at #95 only
  `swapBackend.ts:120` exports it. The file loads, then every track call throws.
- Nothing catches it: `vitest.config.ts` excludes `*.contract.test.ts`; `tsconfig.json` excludes
  `src/**/*.test.ts` (no test file is typechecked at all); biome doesn't check that an import exists; at #95 CI runs
  only `checkTs`, `lint` and `test`. The daily `test:contract` job arrives only with #102.
- #102 fixes it by moving `callTool` into `swapClient.ts` and re-exporting it from `swapBackend.ts`. #96, #97 and
  #98 are still broken.
- Fix: bring #102's move down into #95.
- Guard: a contract-only tsconfig (noEmit, contract tests plus fixtures) in `checkTs`. It reports this error and one
  more real one: `swapQuote.contract.test.ts:41`, because `getCachedQuote` can now return `"key_mismatch"`.
  Typechecking every test isn't quick: about 20 errors already exist in the unit tests.

### (b) Unbounded retry advice: confirmed, same at #102

- `swap.ts:140` `retryWithoutResend` replaces the stop clause in `RETRY_LATER` ("if it still fails, tell the
  user…") with a bare "Call again in N seconds". Applies to RATE_LIMITED, CHAIN_UNAVAILABLE, UPSTREAM_UNAVAILABLE,
  INTERNAL.
- The server doesn't count attempts. A submit that keeps failing (`success:false`, 5xx) is POSTed again on every
  call: 30 `/submit-tx` POSTs for one deposit over a 15-minute quote. That's 2 of the 10/min the whole IP gets, so
  five stuck deposits use it all.
- `POLL` (`swap.ts:233`) never ends: a row stuck in `pending` still reports `queued` 48 h later (that path doesn't
  need the quote); a pending tx the node has seen stays `awaiting_source_confirmation` even after the quote is gone.
- A dead RPC gives CHAIN_UNAVAILABLE forever and never alerts: only a `logger.warn` (`source.ts:114`), and
  CHAIN_UNAVAILABLE isn't in `ALERTED_CODES` at #102.
- `expired_unsubmitted` ("again in 60 s") is bounded only by the 30-minute grace; after that it turns into
  `unknown_quote` (see c).
- Fix:
  - Return `pollUntil` (the quote's `expiresAt`, or about 30 min without a quote).
  - Retry text: "…until <pollUntil>; then stop, tell the user the deposit is safe, and give SODAX the txHash".
  - Past `pollUntil`, track returns a final `stalled` status and alerts from the checked-deposit budget.
  - Store `lastSubmitAt` on the quote; don't POST again within 60 s.
- Tests: a pending row past the grace returns no `retryAfterSec` and alerts; 10 failing submits make at most N
  POSTs; the retry text contains the stop clause.

### (c) Alert capacity for stranded deposits: confirmed at #95, worse at #102

- `alerts.ts:38-39`: `unknown_quote` (a deposit whose quote was lost in a restart; only an operator can move it)
  shares 5/h with `other_quote_deposit`. Both are free to trigger: any key, a random uuid, `chain`, and 5 public
  deposit hashes. After 5 such calls a real lost-quote deposit is only logged.
- Track still answers `alerted: true` and "SODAX has been alerted" (`track.ts:236`, `swap.ts:270`). The status is
  final, so the "posted on a later call" path (`alerts.ts:63`) never runs. The hourly summary (`alerts.ts:88-95`)
  carries only a count, no tx hashes.
- A checked deposit whose refund relay keeps failing becomes `unknown_quote` once the quote leaves the cache, so it
  also lands in the budget anyone can fill.
- At #102, `swap_error` uses the same budget as checked deposits (`alerts.ts:82`; its test "counts tool errors
  toward the same hourly cap" asserts this). 20 different tool errors in an hour (one PRICE_OFF_MARKET per source
  chain, or a burst of INTERNAL during an outage) silence `refund_relay_failed` and `submit_rejected`.
- Fix:
  - Separate budgets: stranded (checked deposits), public, tool errors.
  - Keep held-back deposit alerts (kind, chainKey, txHash) in a bounded list and post them in the hourly summary.
  - `alertOperator` returns posted or held; set `alerted` from that.
- Tests: 25 `swap_error` + 25 public alerts, then one `refund_relay_failed` still posts; 6 `unknown_quote` alerts →
  the summary contains the 6th tx hash.

## New findings

1. BLOCKER, still at #102: errors after the deposit is claimed get quote-time advice.
   - `track.ts:178` (submit) and `:252` (refund relay) only treat `SWAP_REJECTED` as a refusal (verified:
     `if (!(error instanceof ActionError && error.code === "SWAP_REJECTED")) throw error;`). Any other non-retryable
     error after the deposit is checked and claimed reaches the agent with the advice meant for quoting:
     - submit 400 `{code:-23}` → AMOUNT_TOO_LOW, "Ask the user for a larger amount."
     - 401 or 403 → API_KEY_REQUIRED, "Ask the user for a valid SODAX API key".
     - no alert, no "don't send it again".
   - Failure: the key is revoked, or a WAF answers 403 on the POST. The agent gets a new key, the old quote gives
     QUOTE_KEY_MISMATCH, the agent quotes again, the user deposits twice. The first deposit is stranded and nobody
     is alerted.
   - Fix: once the deposit is claimed, every non-retryable submit or relay error alerts and returns the
     deposit-is-safe wording. Apply "don't send it again" to all codes in track and cancel, not only the retryable
     ones (`actionTool.ts:38-41`).
   - Test: 400/-23 and 401 on submit both log an alert, and nextStep contains "must not send it again".
2. should-fix: PR body doesn't match the code. It says track contract tests exist (they can't run, see a); 567 unit
   tests (now 615); the "5 for deposits whose quote is gone" budget also covers `other_quote_deposit`; cancel "waits
   for the receipt" (it returns `cancel_awaiting_confirmation`).
3. should-fix, still at #102: tests that claim more than they check.
   - `swapTrack.test.ts:679` ("says when to stop calling") only checks the tool description; error nextSteps have no
     stop.
   - `swapTrack.test.ts:673` ("needs a valid key to submit") checks only the error code on a claimed deposit, which
     hides finding 1.
   - `alerts.test.ts:33` asserts `not.toContain("dEaD")`, but the test fields contain no address, so it proves
     nothing.
   - `swapCancel.test.ts:285` locks in "never submitted, call sodax_swap_track first" for a deposit this server
     already submitted while the backend row lags.
4. nit: track accepts the receipt as soon as the tx is mined, no confirmation count (`sodax.ts:183`). On a
   reorg-prone chain like Polygon, a reorg plus a replaced tx puts the deposit under a new hash → `quote_used`,
   manual recovery.
5. nit: `quoteId` isn't lowercased but cache keys are. An upper-cased id reads as a lost quote, so it alerts
   `unknown_quote` while the real quote sits there unsubmitted.

## Checked and fine

- Double submit: blocked by the in-flight key, the claim, and reading status first.
- Mismatched relay: a deposit is claimed only after it matches the quote.
- Tx hash from another chain: the receipt and the `Message` srcChainId are read on the quote's pinned chain.
- Multiple deposits in one tx: refused.
- Cancel by another key: QUOTE_KEY_MISMATCH before anything is read.
- Cancel on a filled intent: refused; if the row lags, it costs only gas.
- Deadline boundaries: `<` for submit and `>=` for relay, tested at 359 and 361 s.
- URL leaks: none in alert fields or error text; RPC errors wrapped by `bounded`.
- After a restart: consistent with the settled decisions.
